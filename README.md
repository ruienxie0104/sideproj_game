# 借空間 · 鄰居的小願望

手機優先、單指操作的空間分配解謎原型。**按住一間房，向鄰居借空間，直到每個小家都舒服。**

目前是可玩性驗證版本 `0.2.0`，不是已驗證留存、收益或原創性的商業成品。

## 開始遊玩

需要 Node.js 20 或更新版本，無須安裝套件。

```bash
git clone https://github.com/ruienxie0104/sideproj_game.git
cd sideproj_game
npm run dev
```

開啟 [http://localhost:4173](http://localhost:4173)。也可把 `dist/` 放到一般靜態網站主機。請透過 HTTP/HTTPS 開啟；直接雙擊 HTML 的 `file://` 模式不支援 JavaScript modules。

### 用手機測試

電腦與手機連同一個可信任的 Wi-Fi，執行：

```bash
HOST=0.0.0.0 npm run dev
```

手機瀏覽器開啟 `http://電腦的區域網路IP:4173`。`localhost` 在手機上代表手機自己。只需電腦試玩時，使用預設的 `npm run dev`，僅綁定本機。

可用 `PORT=4174 npm run dev` 更換連接埠。手機主畫面安裝外觀有 manifest；尚未加入 service worker，不承諾離線可用。

## 第二版有什麼不同

第一輪試玩回饋是「概念不錯，但玩法、規則與畫面單調」。第二版把同一種面積分配，擴成不同住戶的需求組合：

| 住戶 | 願望 | 第一次出現 |
| --- | --- | --- |
| 小糰子 | 面積足夠 | 第 1 關 |
| 兔兔 | 面積足夠，而且沙發要放得下：需要寬度 | 第 4 關 |
| 小熊 | 面積足夠，而且植物要能長高：需要高度 | 第 5 關 |
| 小貓 | 面積要在舒適範圍：太大也睡不著 | 第 9 關 |

三個街區：暖陽小巷、森林公寓、星光屋頂，共 12 關。加入不同住戶與家具、主題配色、完成願望的粒子與表情回饋、過關星星、下一關預告，以及三件街區收藏。

已玩過第一版可直接從「街區地圖」進入 **第 4、5、9 關**體驗新規則。

## 怎麼玩

- 按住房間：向同層另一間房借寬度，向相鄰樓層借高度。放開停止；輕點能微調。
- 看房間上方的願望與下方的文字，知道還需要空間、寬度、高度，或要把多的空間分出去。
- 所有願望同時完成，即過關。已舒服的房間仍可能因分享空間而不舒服。
- 每關三顆星：完成小家、在目標調整次數內完成、沒有使用提示。**沒有倒數，沒拿滿星也能繼續。**
- 可復原最近 100 次調整。復原會還原次數，但不抹除本局已使用提示的紀錄；重來才重新開始計算。
- 完成一個街區的四關，即收到一件紀念小物；重玩同一關不會重複累加星星。
- 街區地圖可直接選擇所有關卡；`?` 可查看說明。
- 電腦用 Tab 選房間，按住空白鍵或 Enter；音效預設關閉。
- 紀錄只儲存在瀏覽器。第二版使用 `borrow-space-v2`，保留第一版 `borrow-space-v1`，兩版成績不混算。

## 開發與驗證

```bash
npm test       # 規則測試
npm run check # JavaScript 語法 + 規則測試
```

GitHub Actions 對推送和 PR 自動執行 `npm run check`。目前 38 項測試涵蓋十二關的可解路徑、星星目標在 30/60/120Hz 下可達成、面積守恆、相鄰借用、尺寸下限、形狀與最大面積需求、獎勵規則及紀錄清理。

**自動測試通過不等於手機實測通過。** 本次瀏覽器自動化被存取政策阻擋，尚未完成實際瀏覽器畫面、觸控、iOS Safari / Android Chrome、音效和輔助科技驗證。詳見 [驗證紀錄](docs/VALIDATION.md)。

## 專案結構

```text
dist/                可直接部署的靜態網站，同時是目前的前端原始碼
  engine.js          純規則、關卡與提示搜尋
  game.js            輸入、畫面、對話框、動畫與音效
  art.js             原創程式繪製 SVG 角色、家具與圖示
  progress.js        分版進度資料、成績清理與累積規則
  index.html         介面與語意結構
  style.css          手機優先版面
scripts/serve.mjs    無相依的本機伺服器
tests/              規則、進度與跨更新頻率的操作路徑測試
docs/               設計依據、試玩計畫、驗證狀態
```
